# 点定旅途 · 景点库规则（2026-10-17 生效）

> 一句话：每个城市 **45–65 个「值得专程去」的点**；**名称与坐标必须对应高德地图的真实 POI**；
> 不许演出/体验类、子设施、店铺冒充景点。库是**旅游规划**的库，不是本地生活指南。

---

## 1. 数据字段（每个景点必须满足）

| 字段 | 规则 |
|---|---|
| `id` | 稳定不变（分享链接 / 反馈引用它） |
| `name` | **与高德官方名一致（全库无例外）** |
| `coord` | `[lng, lat]`，GCJ-02，必须来自高德 POI 实体 |
| `coord_src` | 只允许 `amap`；**`estimate`（估算坐标）一律不入库** |
| `amap_poi_id` | 高德 POI ID（可随时复验） |
| `verify_src` / `verified_at` | 核验来源与日期 |
| `cat` | 11 类：古迹 / 博物馆 / 山水 / 古镇 / 夜景 / 演出 / 亲子 / 街区 / 美食 / 商圈 / 公园 |
| `heat` | 5–10，由评分推导：`score = 0.6·norm(rating) + 0.25·level + 0.15·curation`，`norm = clamp((rating−3.5)/1.5)`，`heat = round(5 + 5·score)`；跨城可比 |
| `dur` | 建议游览分钟数（古镇/山水 180，① 亲子 210，古迹 120，公园/街区 90…） |
| `tags` | ≤3 个语义标签；「早去 / 夜景」会被引擎 slotFix 消费，不可随意改 |
| `intro` / `reason` | 文案，遵守 `skills/travel-copy` 文体；`reason` ≤24 字、无数字/夸张词；`copy_src='ai'` 表示 AI 生成（约 52%），其余为手写/早期文案 |
| `open` / `open_text` / `closed_mon` | 营业时间（高德 `biz_ext.open_time`；24 小时→`00:00-23:59`；闭馆日只认明确文本） |
| `tel` / `rating` / `cost` / `photo` | 高德回填；**评分满分 5 分** |
| `a_level` / `keytag` | **高德景区等级**（5A/4A/3A，来自 `biz_ext.level`/`keytag`）——"非常知名"的权威判据，5A/4A 豁免删除 |
| `entrance` / `navi_poiid` | 高德**入口坐标**与导航点（比 POI 中心更准，最大实测差 1.4km） |
| `photos`（≤3） / `address` / `district` / `adcode` / `business_area` / `has_children` | 多图、地址、区县、行政区码、商圈名、是否有子景点（子景点用于后续「父子点收敛」） |
| `suburb` | 距城市中心 >25km 视为远郊（远郊日只排远郊点） |
| `added_at` / `note` / `history` | 新增日期 / 备注 / 改名历史（`name_locked` 机制保留但**当前 0 条**） |

## 2. 构成目标（每城）

| 类目 | 目标 | 准入线 |
|---|---|---|
| 古迹 / 博物馆 / 山水 / 古镇 | **26–34** | 评分 ≥4.0 |
| 夜景 / 演出 | 5–8 | 地标级或 ≥4.3（演出类按第 4 条目前一律删） |
| 亲子 | 4–7 | 主题乐园/动物园/科技馆等 |
| 街区 | **≤8** | 限历史文化街区/风貌区（宽窄巷子、南锣鼓巷级） |
| 美食 | **≤4** | 限目的地级美食街（回民街、建设巷级），不收单店 |
| 公园 | **≤5** | 限有景观/历史价值者（西湖、地坛级）；社区公园全剔 |
| 商圈 | **≤2** | 限地标级（解放碑、三里屯、南京路） |
| 远郊 `suburb` | **≥4** | 保证远郊日能成形 |
| 总数 | **45–65** | 宁少勿滥 |

> 超配额的受限类目按**评分从高到低**保留到配额，其余删。**例外**：FAME 名单 / A 级景区（5A·4A）/ 评分≥4.5 的点豁免配额（非常知名不可删），因此个别城市受限类目可能略超配额。
> 小城（供给有限，如敦煌/喀什）允许 **≥20 点**，其余城市 40–65 点。

## 3. 名称与坐标（以高德为唯一准绳）

1. 取数只用高德实体 POI：`/v3/place/detail?id=` 或名称搜索（`extensions=all`）。
2. **采纳官方名**的条件：候选名与我们的名字互相包含，或 ≥3 字公共子串，且通过下列护栏。
3. **护栏（不采纳）**：
   - 子设施：售票处 / 停车场 / 入口 / 馆区 / 产房 / 码头 / 观景台 / 步道 / 驿站 / 游览车…
   - 店铺型：`…(xx店)` 结尾 / 专卖店 / 超市 / 商城 / 公寓 / 骑马场 / 书社 / 服务站
   - 状态括注：`(暂停开放)` / `(装修中)` / `(不对外开放)`
   - 含 `-` 的子区域名（`某景区-北峰`），我们名字无连字符时不采纳
   - 带 `·` / `（` 的复合名（如「人民公园·鹤鸣茶社」）：**只接受完整包含**的官方名，防止被降级成上位景点
4. 名称与坐标必须**同源**（同一个 POI），不允许「名字取 A、坐标取 B」。
5. **全库无人工定名例外**：历史 2 条产品定名（宁波「龙泉山景区」→ 高德官方名「龙山公园」、丽江「文笔水库」本名即与高德一致）已于 2026-10-17 取消，统一采用高德官方名；`name_locked` 机制保留但当前 **0 条**。

## 4. 删除规则（不符合即删，不留）

1. **演出 / 体验类**：`《…》` / 沉浸式 / 戏剧 / 音乐剧 / 话剧 / 舞台剧 / 光影秀 / 水秀 / 演唱会
   （大剧院、剧场、剧院、音乐厅等**场地**除外——它们是地理地点）
2. **核心类评分 <4.0**：古迹 / 博物馆 / 山水 / 古镇 / 夜景 / 亲子
3. **受限类目评分 <4.0**：街区 / 公园 / 美食 / 商圈
4. **无评分且非知名**：知名 = FAME 名单 / POI 类型含风景名胜·国家级 / 评分 ≥4.5
5. **黑名单**：景区/文旅盘性质的低价值点（如麓湖水城）
6. **估算坐标**：`coord_src = estimate` 一律不入库
7. **子设施 / 店铺 / 非地理地点**：不允许作为景点存在

## 5. 必留名单 FAME（22 城，每城 10–20 个）

> 例：宽窄巷子 / 天安门 / 外滩 / 洪崖洞 / 西湖 / 六和塔 / 丽江古城 / 布达拉宫 / 雁荡山 / 拙政园 / 洱海 / 兵马俑 / 卡瓦格博峰 / 老班章 / 文笔水库…

- 作用：**豁免**「受限类目配额」与「评分阈值」删除 —— 非常知名的地标不可删。
- 维护：新增城市必须先在 `scripts/rebuild-library.js` 的 `FAME` 登记，**漏登记会让知名点被配额误删**（已发生过一次，靠 git 恢复 18 个点）。

## 6. 数据来源与核验

- **唯一数据源：高德地图**（官方 API，或转发通道 `https://pass-api.ibtmap.com/a`；脚本用 `AMAP_BASE` / `AMAP_KEY` 切换，不设则回落官方域名）。
- 腾讯地图只在建库早期用于坐标交叉校验，**不再作为权威源**。
- 每条景点都保留 `amap_poi_id`，可随时用 `/v3/place/detail` 复验名称/坐标/评分。

## 7. 采集与复核流水线

**新城市从零建库**（`scripts/build-city.js`，自动化第一遍即合规）：

```bash
node scripts/build-city.js <城市> --apply     # 高德发现候选 → 规则筛选 → 类目配额配平 → 文案 → 建库 + 登记注册表/FAME 种子
node scripts/pipeline.js <城市> --apply      # 已有库城市的补全与复核（biz-info/重构/校验）
node scripts/rebuild-library.js --audit-rules <城市|all> --apply   # 逐点规则复核（可重复跑）
```


```bash
node scripts/pipeline.js <城市> --apply     # 计划内城市一条命令走完
# ① repair-coords 坐标 → ② rematch-llm 别名裁判（仅有估算点时）
# ③ biz-info 官方名对齐 + 营业信息 + POI 校准（含护栏与事后审计 biz-audit）
# ④ rebuild --collect 候选池 → ⑤ rebuild --plan --apply 重构（删弱项/配额/FAME/heat 重算）
# ⑥ 校验：heat 越界 0 / 坐标异常 0 / 残留演出类 0 / 重名 0（不达标 exit 1）

node scripts/rebuild-library.js --audit-rules <城市|all> --apply  # 逐点复核全部规则（可重复跑）
```

## 9. 与引擎的关系（改库时必读）

- 引擎 `MAX_PER_CAT = 3`：**每天每类目最多 3 站**，所以库的构成直接决定行程质量；
- `heat` 只参与选点与分组排序，**不进时长公式**；
- `tags` 里的「早去 / 夜景」被 `slotFix` 消费（决定早/晚时段），不随意改；
- 改库后必须跑 `engine/test.js`，并重新构建 `web/assets/engine.bundle.js`（若动引擎）→ 部署云函数 + 托管 `data/` → 双端抽验。


## 图片规则（2026-10-19 补充）

1. **每个景点 3 张图**（`photos` 数组，主图 = `photos[0]`，同时同步 `photo` 字段）。
2. **统一 HTTPS**：历史数据里有 http 链接（https 站点下会被浏览器拦截），已全部升级为 https。
3. **高德 CDN 支持 OSS 高清参数**：`store.is.autonavi.com` / `aos-comment.amap.com` / `*.aliyuncs.com` 的图片 URL 追加
   `?x-oss-process=image/resize,w_1440` 可取回**真原图重采样**（例：500×330 缩略图 → 1440×953、体积 66KB→360KB，非放大）。
4. **分辨率门槛**：升级后逐张校验，宽度 <1000px 的图不采纳（回退原图/下一张候选），避免「马赛克/糊图」。
5. **来源**：优先高德 POI 图（`amap_poi_id` 对应的图片），保证同库风格一致；高德无合适图时再考虑外部来源。
6. 前端使用：景点详情/时间轴缩略图/海报统一读 `photos`，`onerror` 自动跳到下一张或首字兜底，不留空白。
7. 海报侧通过云函数 `photoImg` 代理（HTTP 抓取 + base64 + 30 天缓存），避免 canvas 跨域污染；单图上限 700KB。

## 图片加载链路（2026-10-19 修复）

**现象**：规划页部分景点不显示图片（数据里 100% 有图，但浏览器加载失败）。

**根因**：高德 CDN 中 `store.is.autonavi.com` 的图片对**浏览器直连**会返回 `net::ERR_CONNECTION_CLOSED`（服务器端抓取 200 正常；`aos-comment.amap.com` 不受影响）。也就是说不是数据缺失，是 CDN 对浏览器请求的拦截。

**修复**：
1. `photoImg` 云函数新增 **GET 图片代理**：`/photoImg?w=320&url=<高德图>` → 服务端抓取后以二进制返回（`isBase64Encoded`），带 `Access-Control-Allow-Origin: *` 与 30 天浏览器缓存；支持 `w` 参数按需缩放。
2. 前端统一 `DDN.imgSrc(url, width)`：
   - 规划页时间轴缩略图：320px，最多 3 张候选逐张回退，全失败才显示类目占位字；
   - 景点详情抽屉：720px；
   - 海报：720px + `crossOrigin='anonymous'`（canvas 需要 CORS，否则无法导出）。
3. 海报图片改为**浏览器并行加载**（不再走 base64 POST 分块），生成时间 13s → **6s**。

**验证**：杭州 3 天路线（10 站）——规划页缩略图 5/5、详情抽屉 3/3（720px）全部加载；海报 10 张照片全部显示、导出成功；分享页海报生成 6 秒。
