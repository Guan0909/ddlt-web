## 1. 一句话产品定义 + 目标用户

### 1.1 产品定义

**点定旅途（decidenow.asia）= 把「起点 + 城市 + 天数」在秒级变成「几点到哪、怎么走、来不来得及」的钟表级路线，并输出一张可保存的真实地图多色海报。**
Slogan：**把今天，点定成一条路线。**（`01-最终方案-V4.0.md:4-5`）
形态：响应式 H5（移动优先，不做小程序），**匿名免登录、URL 即分享**；算法排序、AI 只做解释层（`01-最终方案-V4.0.md:12-15`）。

### 1.2 三条价值主张（每条都对应竞品未满足点）

| # | 价值主张 | 用户原话式表述 | 竞品空缺/证据 |
|---|---|---|---|
| 1 | **时间可执行**：每一站有到达/离开时刻，12:00 与 18:00 两个用餐槽，19:30（远郊 20:30）收束 | 「不是给我一堆景点，而是告诉我 9:03 到博物馆、11:12 到下一站」 | 8 款竞品均无时钟级时间轴；AI 类产品「时间/日期/预算等硬信息不可靠」是通病（`竞品分析-8款.md:13,84`） |
| 2 | **计划可微调、结果可解释**：上移/下移/删除/换一站/时长 ±15min/移到另一天；排不下的点明示原因 | 「临时少玩一处，不用整条重排」 | 竞品多为「生成完即定型」或拖拽式手动排序；Wanderlog 核心能力锁付费（`竞品分析-8款.md:11,20`） |
| 3 | **成果可带走、可传播**：真实地图底图 + 每日一色路线 + 景点图的海报，只读链接随手分享 | 「发给同行的人，不用截图九宫格」 | 8 款竞品导出仅长图模板 / Excel / PDF / 付费导出，**真实地图多色海报 0 款**（`竞品分析-8款.md:17,22`） |

### 2.3 差异化空白结论：为什么这个切口成立

1. **组合空白已被矩阵验证**：8 款里没有任何一款同时做到「时钟级时间轴 + 开放时间约束 + 真实地图多色海报」（`竞品分析-8款.md:22`）。
2. **需求侧有真实痛点**：横评文章与独立调研一致——AI 旅行工具「时间/日期/预算等硬信息不可靠」是通病（飞猪日期理解错、马蜂窝/携程/高德时间不准），这正是「排序归算法、AI 只做解释层」的对赌点（`竞品分析-8款.md:31,84`）。
3. **供给侧不需要重资产**：不需要大模型能力、不需要 POI 供给、不需要预订供应链；核心资产是「精选库 + 排序/时钟算法 + 地图渲染」，一个人 + 免费额度即可启动（`技术可行性与架构评估.md:100-108,142`）。
4. **中立性本身就是差异**：携程/马蜂窝的导流绑架与同质化差评，反衬「不预订、不社区、不导流」的工具中立（`竞品分析-8款.md:18-20,50`）。
5. **传播有免费载体**：海报是天然获客素材，竞品要么没有、要么是长图模板（`竞品分析-8款.md:17`）。

### 4.2 六条不可违反红线（写进每一条开发提示词）

1. 路线排序永远由算法完成，AI 只写解释性文案，不得生成地点/坐标/营业时间/价格。
2. 腾讯位置服务 Key 只出现在云函数环境变量；前端只有公开 GL Key（域名白名单）。
3. 单次路线生成腾讯 API 调用 ≤15 次（批量矩阵 + 起点 200m 网格缓存）。
4. 一切 AI 输出必须可降级（默认 3s、叙事 5s 超时，失败前端整行隐藏）。
5. 视觉遵循原型体系（纸白 #FAFBF8 / 主绿 #3B7356 / 墨色 #182119 / 发丝线 / 衬线大标题）。
6. 无登录、无支付、无 UGC 发布；分享页只读，`route_id` 为 128 位不可猜测 ID。

### 5.5 AI 协作开发模式（重要的产品叙事，不是技术细节）

> 这是「一个人如何完成全栈产品」的方法论，可作为简历/面试的核心叙事。

1. **分阶段提示词迭代，而不是一次性生成**。把开发拆成 P0 主上下文 → P1 引擎 → P2 数据回填 → P3 前端 → P4 云函数部署 → P5 海报 → P6 AI 文案，每阶段有可判定的验收闸口（P1 成都数据跑出合理时间轴、P2 坐标回填报告、P3 全链路走通、P4 配额实测 + 降级演练、P5 低端机实测、P6 断 Key 全流程无碍）（`03-开发模式评估.md:24-35`、`02-AI提示词全套.md`）。
2. **为什么这样选**：① 存在未验证的外部依赖（腾讯配额、静态图多色叠加、Canvas 跨域），第 1–2 周就要暴露风险；② 模块间有明确验收闸口；③ 全貌远超单次会话有效上下文，分阶段让每段只携带「主上下文 + 当前阶段」；④ 单人项目没有 code review，「验收清单驱动」是唯一可靠的质量闸门（`03-开发模式评估.md:5-10,12-22`）。
3. **文档即规格**：方案、红线、接口契约、算法常数全部落盘；`项目上下文.md` 定位为「唯一事实入口」，每条结论附 `文件:行`，改动后同步更新（`项目上下文.md:3-5`）。提示词里写明「超出 V1.0 范围的功能一律记入 V2 候选」，防止 AI 自行加需求（`02-AI提示词全套.md:110-114`）。
4. **AI 并行做研究与审查**：V4.2 用 3 个子代理并行调研地图能力边界（`06-底图风景名胜驱动-V4.2.md:8`）；V4.1 对已上线代码做全量只读审查 + **440 组随机构型回归扫描**（`05-算法审查与校验优化-V4.1.md:3`）；UI/UX 用无头浏览器 CDP 实测全流程并留截图证据（`ui-ux-review.md:3-4`）。
5. **结果**：计划 6 周 → 实际 9 个日历日完成 0→60 城上线；128 次提交；约 1 万行手写代码；1,258 行方案/审查文档；首版在方案定稿后约 18 小时上线。**注意口径**：这是日历时间与产出量，不是工时/人日，也不是「6 周计划按时完成」。
