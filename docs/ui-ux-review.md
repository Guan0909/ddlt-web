# 点定旅途 · UI/UX 审查与优化方案（2026-10-18）

> 方法：无头浏览器实测全流程（首页 → 建议 → 加载 → 结果 → 编辑旅途 → 分享 → 海报）+ 代码走查（index / loading / result / share / poster / app.js）。
> 截图证据：`build/a1-home.png`、`build/a2-city-drawer.png`、`build/b1-suggest.png`、`build/c1-result.png`、`build/c3-edit.png`、`build/c4-edit-search.png`、`build/c5-share.png`、`build/ui-poster-alevel.png`、`build/ui-result-alevel.png`

## 一、总体判断

视觉系统（纸白/绿/墨、衬线大标题、发丝线）统一且高级，Hero、统计行、Day 标签、海报都达到「可发布」水准。
问题集中在**信息密度与操作语义**：结果页把「浏览」和「编辑」两套界面揉在了一张卡片里；编辑态丢失了「当前在改哪一天」的上下文；搜索建议噪声大。以下按屏幕列问题、按优先级给方案。

## 三、优化方案（按优先级）

### P0 · 主流程与信任（建议先做，约 2–3 天）
1. **结果页「浏览态 / 编辑态」分离**
   - 浏览态卡片只保留：名称 + A 级徽章、类目标签、缩略图、事实行（评分/营业/电话）、一句 reason；
   - 「时长档 + 上移/下移/换一站/移到另天/删除」收进「编辑旅程」开关（进入编辑后才展开），或卡片右下角「⋯」展开；
   - 收益：一屏可见 2–2.5 张卡，行程可读性大幅提升。
2. **编辑模式补「当前编辑天」上下文**
   - 顶部地图区加 Day 胶囊（D1/D2/D3 可点切换），并在底部显示「D2 · 已选 3 站 · 预计游览 4.5h · 通勤 0.8h」；
   - 「取消」改为「完成」/「返回」二选一，去掉语义重复。
3. **修缩略图破图**：`img.onerror` 时隐藏图片并回退为 A 级/类目色块占位；加 `loading=lazy` 已有，补 `decoding=async`。
4. **搜索建议治理**
   - 过滤类型：地铁站/公交站/停车场/购物中心/超市/便利店/公司等；
   - 同城优先、外地同名降权并标注「外地」；已开通城市优先；
   - 列表项加类型图标（景点/酒店/交通/商场），选中态更明确；
   - 加 150ms 骨架/「正在搜索…」占位，避免空白。

### P1 · 顺滑与信息利用（约 2 天）
5. **首页**：裸文本也允许生成（按钮 enabled，文案「回车即可，我们帮你解析」）；城市抽屉加搜索框 + 「最近去过/热门城市」两行；页脚精确显示 60 城并可点开城市列表；加「看一个示例路线」。
6. **结果页卡片点开轻详情抽屉**：多图（≤3 张，已采集 100%）、完整地址、营业时间原文、A 级标签、电话、评分，「去这里」唤起高德导航。
7. **编辑模式地图降噪**：标签碰撞避让（或只在放大后显示名称）+ 底部提示条与水印错位修正。
8. **加载页**：显示已耗时与阶段文案（「正在写入时刻表…」），>12s 出现安抚提示；失败态给「重试 / 换起点 / 返回首页」。
9. **分享页**：加静态路线缩略图（复用海报底图能力）+ 「我也要生成」主按钮上移。
10. **去掉「AI 文案」标签**（改「智能排线」或直接删除），避免信任折损。

### P2 · 打磨（约 1 天）
11. 结果页 Day tabs 吸顶 + 滚动联动地图（滚动到某天时自动切图）。
12. 通勤占比提示（>40% 时给出「减少远郊点/换交通方式」建议，纯前端文案）。
13. 触控目标 ≥44px；toast 支持一个主操作（"撤销"）。
14. 海报底部加短链域名（decidenow.asia）增强品牌记忆。
15. 骨架屏统一（首页建议、结果卡片、分享页）。

## 四、验收口径

- 结果页：3 天行程在 430×932 视口下，浏览态「不展开任何操作」可一屏看到 ≥2 张完整卡片；
- 编辑模式：进入后 1 秒内能看到「正在编辑 D2」；
- 搜索：输入「天府广场」前 3 条均为地理地标且同城优先；
- 图片：任一卡片图片加载失败时显示占位色块而非破图/alt 文本；
- 分享/海报：A 级徽章、评分、路线统计完整，无遮挡。

## 六、起点搜索逻辑线重构（2026-10-18 下午）

### 问题（用户指出的三处矛盾）
1. 起点搜索混用「景点库 + 云端」：本地库只在已选城市内有数据，导致不选城市就搜不到；
2. 城市必选 → 右上的「选择城市」与搜索框形成互斥前置条件，逻辑不顺；
3. 用户输入不完整名称（如「天府广」）时，此前可能把半截字符串当起点，路线里显示的名称不完整。

### 新逻辑线（已实现）
| 入口 | 行为 |
|---|---|
| **搜索框（唯一主入口）** | 输入即调**云端腾讯关键词提示**（不再用景点库）；全国可搜（已选城市时同城优先）；300ms 防抖 + 「正在搜索…」占位 + 无结果文案；过滤地铁站/公交站/停车场/购物中心/子入口（如「天府广场-A口」「-东南入口」）等噪声 |
| **选中建议** | 回填**完整官方名称**（如「天府广」→「天府广场」）；按 POI 城市**自动切城**；未开通城市标「未开通」并提示 |
| **回车** | 自动选中第一条建议（保证「不完整输入 → 完整名称」）；无建议时直接提交，由加载页强匹配解析 |
| **定位按钮** | 逆地址返回的**完整地址**作为起点名（如「四川省成都市青羊区西御街」），自动切城，显示「已定位：…」；失败给友好提示 |
| **选择城市（可选）** | 仅用于「按城市快速开始」（不写起点则从市中心出发）；不再是搜索前置条件 |
| **加载页兜底** | 裸文本起点由 searchPoi 强匹配解析为完整名称，并**回写请求快照**——结果页与返回首页都显示完整名称 |

### 附带修复的基础设施问题（关键）
- **Vercel `/api` 代理已失效**：`ROUTER_EXTERNAL_TARGET_CONNECTION_ERROR`（20s 超时/502），导致线上云搜索、云端排线、海报底图全部不可用；
- 浏览器**直连 CloudBase 会被 CORS 预检拦截**（HTTP 触发器对 OPTIONS 返回 400）；
- 修复：前端改用 `Content-Type: text/plain` 的**CORS 简单请求**直连 CloudBase（无预检），云函数 `parseBody` 增加 **base64 body 解码**兼容；8 个云函数已重新部署。
- 效果：浏览器内 `cloudPost` 实测 2.2s 返回 10 条结果；云端排线、海报底图恢复。

### 验证（无头浏览器实测）
- 输入「天府广」→ 建议 3 条干净结果（天府广场 / 酒店 / 主席像）→ 回车 → 输入框变「天府广场」、自动切成都、提示「起点：天府广场」→ 生成 → 结果页「成都 · 三日」「从天府广场出发」✓
- 定位 → 输入框「四川省成都市青羊区西御街」、提示「已定位：…」、城市自动切成都 ✓
- 云端 posterImg 走新通道：海报图正常渲染 ✓

## 七、出发时间 / 每日站数 / 卡片时长交互（2026-10-18 晚）

### 需求
1. 取消「现在就走」切换；把「明早 09:00」改成**可点选的时间选择器**，并按出发时间决定一天能排几站（9 点≈全天、14 点≈半天）；可选更优时间方案；
2. 不再有「一天必须 3 个景点」的限制，按游玩时间一天可排更多；
3. 卡片里删除「信息有误」；「2h/2.5h…」这一行要标明是**游玩时长**且可点选调整。

### 实现
| 项 | 做法 |
|---|---|
| 出发时间交互 | 结果页时间条改为可点：`按 HH:MM 出发 · 全天/大半天/半天 · 改时间 →`；点开抽屉提供 07:30 / 09:00 / 10:30 / 12:00 / 14:00 / 16:00 六档（含时长说明），选择后云端重排并刷新；晚出发时追加提示「想多玩几处可改早一点」 |
| 按时间定站数 | 引擎新增 `opts.startMin`（仅作用于第一天，默认 09:00，范围 05:00–16:00），窗口 09:00–19:30 ± 出发时间自然决定容量；日游览容量随出发时间动态调整（480–720 分钟） |
| 取消 3 站限制 | `MAX_STOPS_PER_DAY` 5→8、`MAX_PER_CAT` 3→4；原「单日游览 >480 分钟即挪点」改为随出发时间放宽（早出发最多 720） |
| 卡片时长 | dur-row 前加「游玩时长」标签（带 title 提示），点选档位后时间轴自动重排；「信息有误」按钮移除 |

### 实测（无头浏览器 + 云端）
- 09:00 出发：首日 **6 站**（此前约 3 站），全库同城数据下总 9 站；时间条「按 09:00 出发 · 全天」
- 选 14:00：时间条变「按 14:00 出发 · 半天 改时间 → 想多玩几处可改早一点」，首日 **3 站**、总 7 站，D1 时刻表从 14:00 起
- 16:00：首日 1 站（只排近处）
- 卡片：出现「游玩时长」标签与档位（1h/1.5h/2h…），无「信息有误」

### 顺带修复
- 引擎 `clampStartMin(null)` 被 `Number(null)=0` 误判为 05:00（导致首日排到 7 站）→ 已加空值判断；
- 云端 genRoute 支持 `startMin`（'HH:MM' 或分钟）；引擎 bundle 与 3 个内嵌引擎的云函数已重建部署。

### 实现

## 十二、路线规划与地图渲染优化（2026-10-19，参照主流地图）

### 诊断（为什么「杂乱 / 缩小后不明显 / 顺序不合理」）
1. **渲染**：同一天拆成多条腿各自成层 + 白色光晕 (6px) → 交叉处层叠发闷；线宽固定 3px → 缩小后视觉权重不足。
2. **假几何**：公交（transit）腿的 direction polyline 常是简化直线，被当成真实路径画实线 → 出现「跨湖直线」；单腿失败时也画实色直线。
3. **排序**：日内排序先按空间贪心 + 2-opt，再用「早去/夜景」标签强行分组（夜景点一律压尾、早去点一律靠前）→ 容易产生「西→东→西」折返。

### 参考的成熟做法
- Google Routes Preferred：`polylineQuality` 支持 OVERVIEW（低细节概览折线）/ HIGH_QUALITY（高精度）两档 —— 同一路线按缩放给两套几何。https://developers.google.cn/maps/documentation/routes_preferred/config_poly
- Mapbox Directions：`overview=simplified|full` 同样是概览/完整两套几何。https://docs.mapbox.com/api/navigation/directions/
- Google OR-Tools 车辆路线（TSP/VRP 求解器）：站点数更多时可用它替换启发式排序。https://developers.google.com/optimization/routing

### 已实现
| 层 | 改动 |
|---|---|
| 渲染 | 相邻腿在站点处合并为**一条连续折线**；主线加粗（5–7px 随缩放）、**去掉白色描边**、实色圆角；站点标签加序号「1. 苏堤春晓」；失败腿改**浅色虚线**兜底（不再冒充真实路网） |
| 双模式 | 缩放 <12.6 用**概览示意线**（平滑、干净）；放大到 12.6+ 才显示真实路网细节，解决「缩小后杂乱/不明显」 |
| 排序（引擎） | 代价函数加入**线段交叉惩罚**（每处 ≈600m）与**折返惩罚**；2-opt 按代价优化；「早去/夜景」标签改为**软约束**（强行重排使代价 >8% 则放弃） |
| 排序（云端 refine） | 真实通勤分钟口径再加交叉/折返惩罚；与时段分组顺序比较择优（空间更顺且不明显绕路时采用） |
| 数据 | transit 腿改用**驾车路网几何**；新增**几何可信度校验**（绕路系数 <1.02 或偏离直线 <max(20m, 3%) 判为假路径 → 前端虚线兜底） |

|---|---|---|
| 线段交叉 | 6 | **0** |
| 折返 | 8 | **1** |
