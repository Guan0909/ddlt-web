# 02 · 新会话 AI 提示词全套

> 用法：新会话先贴 **P0 主上下文**（建立地基），然后按阶段顺序贴 P1→P5。每个阶段验收通过再进下一段。
> 所有提示词假设工作目录为项目根目录（含 `prototype/`、`brand/`、`data/`）。

---

## P0 · 主上下文（每次新会话首先粘贴）

```
我要开发一个已定型方案的网站产品「点定旅途」（域名 decidenow.asia）。
【环境前提】本会话工作目录应为项目根目录 D:\kimi files\点定旅途。
请先读取以下文件建立完整上下文（若相对路径读取失败，告诉我，我会改用绝对路径或粘贴内容）：
- 方案：新会话启动包/01-最终方案-V4.0.md
- 架构：技术可行性与架构评估.md
- 原型：prototype/（start.html / result.html / share.html / poster.html + assets/style.css，视觉已定稿，开发需还原其设计语言）
- 数据：data/spots/chengdu.json（成都 64 个景点的富化库样板）、data/cities.json
- 品牌：brand/（logo/字标/头像/封面）

不可违反的红线：
1. 路线排序永远由算法完成，AI 只能做解释性文案，不得生成地点/坐标/营业时间/价格；
2. 腾讯位置服务 Key 只允许出现在云函数环境变量，严禁前端落地；
3. 单次路线生成的腾讯 API 调用 ≤15 次（批量距离矩阵 + 起点 200m 网格缓存：步行/驾车 TTL 7 天、公交当天）；
4. 一切 AI 输出必须可降级（3 秒超时回退模板文案）；
5. 视觉遵循原型既有体系：纸白 #FAFBF8、主绿 #3B7356、墨色 #182119、发丝线 #E3E8E0、衬线大标题、编辑感简约风；
6. 无登录体系、无支付、无 UGC 发布；分享页只读，route_id 用 128 位不可猜测 ID。
确认你已理解，然后告诉我你准备的第一步，不要直接开始写代码。
```

## P1 · 路线引擎（纯 JS，不依赖外部 API，可先行）

```
任务：实现路线生成引擎 engine.js（纯函数、零外部依赖，可在浏览器或 Node 运行），并做一个测试页用成都真实数据跑出可视化时间轴。

输入：spots 数组（读 data/spots/chengdu.json，coord 字段为 [lng,lat] 估计值，测试阶段直接用）、起点 {lng,lat,name}、天数 1~5。
输出：按天分组的路线，每站含：名称、到达时刻、离开时刻、游览时长；段间含通勤方式（<1.2km 步行 / 1.2~8km 地铁公交 / 其余打车）、估算分钟（步行 80m/min、公交按 20km/h、打车按 30km/h 的直线距离估算，乘 1.2 候车系数）。

算法要求：
1. 多日：候选点按坐标 K-means 聚类（K=天数），跨天去重；起点命中库内景点则固定为 D1 第 1 站；
2. 单日：贪心最近邻出初序 → 2-opt 优化 → 时钟推演（从 09:00 起，12:00/18:00 各插 1h 用餐槽，19:30 收束，超出从末尾剔除）；open/closed_mon 已知的做硬约束（闭馆日剔除、停止入场前必须到达）；
3. 距离先用哈弗辛直线距离（引擎与地图解耦，真实路网距离由适配层后续注入）。

验收：给我一个 HTML 测试页，加载成都数据，能从"春熙路亚朵酒店(104.0765,30.6570)"生成 3 日时间轴并打印每站时刻表；D2 应包含大熊猫基地（城北），D1/D3 不应出现跨区域折返。
```

## P2 · 数据回填流水线

```
任务：写坐标回填校验脚本（Node，离线跑）。
流程：读 data/spots/*.json → 对每条调用腾讯地点搜索 WebService（Key 从环境变量 TENCENT_LBS_KEY 读，请勿写进代码）按"城市+名称"搜索 → 取第一条结果的坐标与 POI ID 回填 → 名称相似度低或查无结果的标记为 dropped 并输出清单 → 写回 spots（coord_src 改为 "tencent"，保留原 estimate 坐标到 coord_estimate 字段备查）。
同时输出每城报告：总数/回填成功/剔除数/待人工确认数。
注意：控制请求频率 ≤3 QPS；失败重试 1 次；全程不打印 Key。
验收：成都 64 条跑完，输出报告；抽 5 个知名景点人工核对坐标偏差 <500m。
```

## P3 · H5 前端主体

```
任务：基于 prototype/ 的视觉定稿开发正式 H5 前端（原生 JS，无框架），页面：start / result / share / poster 预览。
要求：
1. 还原原型设计语言（衬线大标题、发丝线、白绿主题、编辑感），桌面端结果页改为左时间轴右大地图分屏，移动端全幅地图+上滑时间轴抽屉；
2. 地图用腾讯 JS API GL（Key 走 lbsProvider 适配层，该层封装搜索/逆地址/距离矩阵/路径规划/静态图五个能力，腾讯为第一个实现，接口签名与高德解耦）；
3. 结果页微调（上移/下移/删除/换一站/时长±15min/移到另一天）走 reRoute 局部重算，换一站后必须全量时间窗重校验，超预算明示后果；
4. 时间轴从引擎输出渲染时钟时刻；通勤段标"约 X 分钟·不含候车"；营业状态每站默认一行；
5. 待规划地点池：底部抽屉，支持"粘贴攻略文本"输入（先存 raw 文本，AI 提取在 P6 接）；
6. 真机兼容：iOS Safari / Android Chrome / 微信内置浏览器。
验收：起点搜索 → 生成 3 日时间轴 → 微调 → 分享链接 → 只读页，全链路可走通（引擎先用 P1 的纯 JS 版，云函数在 P4 接入）。
```

## P4 · 云函数与部署（混合架构：Vercel 前端 + CloudBase 后端，不备案）

```
任务：腾讯云 CloudBase 落地 + 前端部署链路打通。决策背景：域名 decidenow.asia 不备案，
因此前端挂海外托管（GitHub + Vercel），后端留在国内 CloudBase，两地以 HTTP 触发器 + CORS 联通。

云函数：searchPoi / genRoute（把 P1 引擎搬进云函数，距离改用腾讯距离矩阵真实路网值，走网格化 dist_cache）
/ reRoute / posterImg（腾讯静态图代理转 base64）/ feedback。
要求：
1. 所有云函数配置 CORS：Access-Control-Allow-Origin 白名单 = Vercel 部署域名 + CloudBase 默认域名 + localhost；
2. Key 双隔离（线上/离线）、单 IP 限频 20 次/分钟、日预算熔断、70% 配额告警日志；
3. spots/ routes / dist_cache / feedback 四个集合按方案建索引；数据库选「云数据库（文档型）」；
4. 前端部署到 Vercel（GitHub 仓库自动构建），decidenow.asia 的 DNS 从旧产品切到 Vercel（切换当天即可完成，旧记录可回滚）；
5. 前端 API baseURL 按环境变量注入（本地=localhost 云函数调试地址，线上=CloudBase HTTP 触发器地址）。
验收：decidenow.asia 打开产品；生产环境生成一条路线，日志确认单次外部调用 ≤15 次；断网/腾讯超时/AI 失败三条降级路径演示通过；
Vercel 域名与默认域名均可访问（默认域名作回滚备份）。
```

## P5 · 海报（Canvas 正式版）

```
任务：实现海报的 Canvas 2D 正式版（原型 poster.html 是 SVG 展示，正式版必须用 Canvas 重绘以便导出图片）。
版式还原原型：报头（城市衬线+日期）→ 真实地图区（posterImg 代理的静态图底图 + Canvas 自绘多色 polyline 与站点，墨卡托投影换算）→ 图例（每日色+线名）→ 三日单行摘要 → 统计行 → 品牌行（无二维码）。
工程要求：宽度 750px、静态图按显示尺寸请求、跨域统一走 posterImg；若实测静态图多色 polyline 不支持，退路=静态图只出底图、路线全部 Canvas 自绘（投影换算代码已有）。
验收：千元机（或 Chrome 低端模拟）生成 3 日海报 <3s 不闪退；导出 PNG 与原型视觉一致。
```

## P6 · AI 文案（可选增强，最后做）

```
任务：接入 GLM-4-Flash（baseURL 走智谱 OpenAI 兼容端点，Key 存环境变量 GLM_KEY，备用 provider=DeepSeek，配置可切换）。
两个接入点：①路线叙事文案（总体推荐语，输入=结构化路线数据，输出≤60 字，3s 超时降级为模板拼装）；②地点池的攻略文本提取（输入=用户粘贴文本，输出 JSON schema 约束的地点名数组，只在 spots 库内匹配，匹配失败丢弃）。
合规：AI 生成内容旁必有"由 AI 生成"标识；输入限 100 字；输出白名单校验。
验收：断 Key 时全流程走模板无报错；AI 输出含幻觉地名时全部被过滤。
```

## 附：提示词使用纪律

- 每阶段开头先说"接着 P0 的上下文，现在做 Pn"，防上下文漂移；
- 每阶段结束让 AI 自报"验收项逐条过一遍"；
- 任何阶段 AI 提议加功能 → 对照 V4.0 §2 范围表，不在表内的一律回复"超出 V1.0 范围，记入 V2 候选"。
