# 点定旅途 · 最终方案 V4.0（落地定稿）

> 本文件合并 V3.0→V3.3 全部迭代 + 竞品分析（8 款）+ 技术架构评估 + 品牌决策，是唯一有效版本。
> 产品：**点定旅途**（decidenow.asia）——从任何地点出发，生成带时钟时间轴的 1~5 日游览路线，一键导出真实地图多色海报。
> Slogan：把今天，点定成一条路线。
> 主题色：舒适白 `#FAFBF8` + 主绿 `#3B7356`（D2 青 `#3E8E9E`、D3 琥珀 `#B08A3E`、墨色 `#182119`）。

---

## 1. 定位与差异化

- **形态**：响应式 H5 网站（移动优先），不做小程序；匿名免登录，URL 即分享。
- **主场景**：行前轻规划（出发前夜）+ 行中微执行（在景区门口想下一站）。
- **竞品验证的无人区**（8 款竞品矩阵结论，见《竞品分析-8款.md》）：**时钟级时间轴 + 营业时间约束 + 真实地图多色海报**三者组合无人在做。不拼规划能力、不碰预订闭环、不做内容社区。
- 原则：排序永远归算法，AI 只做解释层（不生成地点/坐标/时间/价格）。

## 2. V1.0 功能范围（封顶，不再加）

1. 起点输入：POI 搜索 + 定位辅助（失败静默降级为搜索）；起点命中库内景点自动成为第 1 站；
2. 天数 1~5；时间预算自动推算（现在起排 / 明早 09:00，结果页可一键切换）；
3. 引擎：粗筛 → 地理聚类（多日，K=天数）→ 贪心+2-opt → 时钟推演（通勤+游览+12:00/18:00 用餐槽）→ 19:30 收束；营业时间已知者硬约束、未知软提示；
4. 时间轴结果页：总览条（公里/通勤/游览/用餐/站数）+ 全幅地图 + 时钟时间轴 + 分段通勤（×1.2 候车系数，"约/不含候车"）；
5. 微调：上移/下移/删除/换一站（强制全量重校验）/时长 ±15min/移到另一天；局部重算缓存优先；
6. 海报：3:4，真实地图底图（静态图代理转 base64 + Canvas 2D），一天一条配色路线，无二维码；
7. 分享：只读页 URL（不可猜测 route_id）+「复制这条路线改成我的」克隆 + 可见性说明；
8. 待规划地点池（与"换一站"共用数据源）+ 粘贴攻略文本提取地名（AI 仅在真实 POI 池匹配）；
9. 覆盖城市：成都 + 重庆/西安/杭州/北京/上海（6 城验证期）；
10. 反馈：每景点卡"信息有误"按钮。

## 3. 数据方案

- **无详情 API**（已核实）：坐标/名称/分类 ← 腾讯 API；简介/标签/时长/热度分 ← AI 助手离线产出（已交付 `data/spots/chengdu.json` 64 条样板 + `data/cities.json` 60 城）；
- 坐标纪律：AI 产出的坐标全部标 `coord_src:"estimate"`，入库前必须经腾讯地点搜索回填校验，对不上剔除；
- 营业时间：只填确信值（博物馆周一闭馆等），其余 null + 软提示；
- POI 落库协议风险：缓存姿态（30 天刷新、minimal 字段、来源标注、不转售），低风险非零，知情决策；
- 数据结构：`spots{_id,city,name,lat,lng,tencent_poi_id,cat,tags,heat,dur,intro,reason,open,closed_mon,suburb,coord_src,refreshed_at}`、`dist_cache{from_grid,to_id,mode,distance_m,duration_min,updated_at}`、`routes{_id,day_plans,totals,created_at}`、`feedback{}`。

## 4. AI 策略（GLM-4-Flash 免费优先，DeepSeek 备用）

| 用途 | 边界 | 降级 |
|---|---|---|
| 离线建库富化 | 已由 AI 助手直接产出，零运行时依赖 | — |
| 在线叙事文案 | 只写解释性文字；显式"由 AI 生成"标识 | 3s 超时 → 模板拼装 |
| 攻略文本提取 | 输出受 JSON schema 约束，只在真实 POI 池匹配 | 失败 → 忽略输入 |
| 偏好 chips | 不做自然语言（V1.0），chips 直接映射标签权重 | — |

## 5. 技术架构（详见《技术可行性与架构评估.md》）

- 前端：原生 JS + 腾讯地图 JS API(GL) + Canvas 2D；桌面端结果页左右分屏（时间轴|地图），移动端全幅地图+抽屉；
- 后端：微信云开发（云函数 searchPoi/genRoute/reRoute/posterImg/feedback + 文档库 + 静态托管）；**lbsProvider 适配层**（腾讯首实现，高德留门，坐标系同为 GCJ-02）；
- 配额硬指标：单次生成腾讯调用 ≤15 次（批量矩阵 + 起点 200m 网格缓存：walk/drive TTL 7 天、transit 当天）；200ms 节流 + 重试 1 次 + 70% 告警；Key 双隔离、仅存环境变量、单 IP 限频熔断；
- 性能目标：首屏 <1.5s（4G），生成 p95 <2s，海报 1~3s，千元机实测。

## 7. 成本与验证

- 首年 ≈ 300 元（云开发 240 + 杂项）；变现前必须询价腾讯商业授权（最大潜在成本）；
- 验证指标：生成完成率 >90%、海报成功率 >95%、每城 Top20 抽检无硬错误；
- 止损：开发超 10 周 / 完成率 <80% 修不动 / 配额政策致架构不成立 → 关停，损失 ≤ 千元。
